Extensions can now use MIDI ports, OSC endpoints and control surfaces (#311). `architect-input` gains `ports`: `PortMessage` with a JSON form, MIDI and OSC 1.0 codecs, a `PortBackend` trait, `Ports`, an in-process `VirtualPorts`/`VirtualDevice`, and, behind feature `udp`, `UdpOsc`. It also gains `surface`: `Target`/`Targets` (an app's target kinds with a range, a count, and read/write/label/touch/observe), `SurfaceDesc`/`ControlDesc` and the `Surface` engine (banks, feedback, touch, pickup takeover, encoders, sysex or OSC displays). An extension declares `capabilities.ports` (`midi:<name>`, `osc:<host>:<port>`, `osc:listen:<port>`), which the consent screen shows. Through the host service it lists ports (`ports`), opens one (`open_port`), sends (`port_send`), takes what waits (`port_receive`) and closes it (`close_port`), from Luau (`host.open_port`, …), pages (`ports.open`, …), and the WIT world's new `ports`, `open-port`, `port-send`, `port-receive` and `close-port` imports (the wasi guest's `host::open_port`, …). What a port hears is a `port.message` event to the extension that opened it, which wakes a background extension. An app offers targets with `Host::with_targets`, which declares the point `control.surfaces`; an extension contributes a surface there, and the host opens its port and runs it (`Host::surfaces`, `surface_bank`). The lab offers OSC over UDP, a virtual MIDI port, the metronome's tempo and the accent's hue as targets, and `lab.surface` (`ARCHITECT_LAB_SURFACE=1`). API breaks: `MidiMessage` has `PitchBend`, `MidiKind` has `PitchBend`, `Capabilities` has `ports`, `HostRequest` has eight new variants, `contrib::EVENTS` has `port.message`, and the WIT host interface has five new imports.
