Added a network for extensions (#310). Through the host service an extension makes an HTTP request (`fetch`, `hostcall::Fetch`) with its body read whole or streamed a part at a time (`read_body`, `close_body`), from Luau (`host.fetch`, `host.read_body`), pages (`net.fetch`, `net.read`), the WIT world's new `fetch`, `read-body`, `close-body`, `secret-set` and `ask-secret` imports and the wasi guest's `host::fetch`, and in a browser through the browser's own fetch where CORS allows it. Every request, and every redirect the host follows, is checked against the manifest's `capabilities.hosts` as granted; a redirect to another host is refused, not followed. Requests have time and size limits (`net::TIMEOUT`, `net::MAX_BODY`, `net::MAX_STREAM`). A manifest can declare `[[secrets]]` (an API key): the person enters it once through the app's prompt (a new `PromptKind::Secret`, a hidden field), the host keeps it in `net::Secrets` (`Host::with_secrets`; the lab's `extension-secrets.json`, written `0600`, outside every extension's folder) and puts it into a request's header where the header names it (`"Bearer {{secret:api_key}}"`), only for that secret's hosts. No call returns its value. A hook on `doc.created`, `doc.saved`, `doc.renamed` or `doc.deleted` now needs `reads = ["documents"]`: a manifest declaring one without it is refused at load, a run-time `subscribe` is refused, and an installed extension not granted documents does not get the event. API breaks: `HostRequest` has five new variants, `PromptKind` has `Secret`, `Manifest` has `secrets`, `contrib::Rules` has `reads`, and the WIT host interface has five new imports.
