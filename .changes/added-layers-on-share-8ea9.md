Added layers on share links (#528): a share and each audience carry `listen` (`Listen`: page, reference, full; a new link, and a share note without one, plays to reference; an audience never past its share), set with `ShareChange::Listen` and `ShareLinks::audience_listen`. Extensions place a note type's files with `[[share_layers]]` (`ShareLayersDecl`: linear-time globs, bounded by `MAX_PATTERNS`, `MAX_PATTERN_LEN`, `MAX_STARS`); the node takes the highest layer over every extension's rules (a development copy read through its `installed.toml` link), holds every attached file back below Full while a manifest does not read, has an unknown `[[share_layers]]` key or shares its id with another folder (`architect_sites::InstalledLayers`, `Installed`, `Package`), keeps an uninstalled extension's rules by folder in its data dir until forgotten, sets a kept file that does not read aside and holds everything back until acknowledged, and warns of rules a reinstall lowered (`ShareLinks::kept_layers`, `forget_layers`, `acknowledge_layers`, `KeptLayers`, `LayersReport`, `NodeStatus::share_layers`; actions `SHARE_LAYERS_KEPT`, `SHARE_LAYERS_FORGET`, `SHARE_LAYERS_ACKNOWLEDGE`). Patterns and note types match in any case and either Unicode form (`share_layers::fold`). A part of the vault that does not read (`vault_obsidian::Vault::open_reporting`, `walk_vault_reporting`, `architect_sites::listing::open_reporting`) makes placement unknown: a link below Full answers 503 and is not built until it reads. A kept file that cannot be written is a fault like one that does not read. Compiled-in rules come from `Distribution::share_layers` through `node::start_with_layers`. A file above a link's layer is 403 with `x-architect-layer`, by any spelling of it on disk; anything outside a link is the same 404 as a path that is nowhere. Each link is built for its layer (`architect_sites::Options::hold_back`): a held-back file is never copied into it and no page, search index, files page, archive or queue names it; the node refuses it by path from its placement before touching the disk, and an archive under way stops at a file its link no longer serves. A hand-edited `listen` reads in any case. `<link>_files.json` lists what a link serves (size, sha256, layer, URL; `listen`, `max`; 503 while placement is unknown). `SHARE_AUDIENCE_UPDATE` and `listen` on `SHARE_CREATE`, `SHARE_UPDATE` and `SHARE_AUDIENCE_ADD`; the Share sheet shows how far each link and audience plays, and why a change failed.
