Added the npm packages @fasttrackstudio/architect (features/extensions/web; no dependencies) and @fasttrackstudio/architect-cli (`architect-ext build-web`), published on a v* tag once NPM_TOKEN is set. loadExtension runs an extension's WASI component in any web app. Its JS runs in an opaque-origin sandbox frame, its files are pinned by the lock build-web writes (`integrity`), and its capabilities are deny by default: the manifest's [capabilities] within the embedder's grant, checked as hostcall::check checks them, and an embedder's action is never the extension's own. A destructive action needs `confirm`. Each HostRequest op has a typed handler with the capabilities in its context. Also: memoryHost, fetchHandler, mountView (a shadow root, ids prefixed per pane, only allow-listed URLs, no field a form or autofill reads), ArchitectView for React, flood limits, and isSupported. `integrity` is required (`false` loads unchecked). A core module the extension's JS asks for is read only from beside its glue, without credentials, and its memory limit is written in by the sandbox's worker, never on the page's thread. Logs, host requests, data and starts are bounded, and `limits.idle` stops an idle extension. Changed the browser runner (runner.js): every instance now runs in that sandbox frame, Architect's own web pages included; a page with a CSP must name SANDBOX_HASH in script-src (apps/sandbox/web/index.html does). Fixed WASI components in a browser: every host import that waits for the page (notify, pick, documents, fetch, …) is now JSPI-async, so it answers instead of trapping or dropping its error, and the editor and port imports are linked.
