This page is the checklist for #710: every capability an extension needs
to stand in for the top Obsidian plugins, the REAPER-class extensions
Studio needs and our own apps (Health #371, Finance #370, Studio's
setlists), with where it runs today. Every PR in that effort updates the
rows it moves, with its evidence.

The ids are #710's. The first column of evidence is an automated check;
the second is screenshots at 390 px and 1280 px wide, light and dark, for
each platform the row claims.

## Run it and capture it

| Platform | Run it | Capture it |
|---|---|---|
| Desktop | `devenv up` (the local stack: the app on a scratch copy of the demo vault, which is the showcase's, with every showcase extension loaded as below) or `just showcase` (the standard distribution; `just showcase plain` for Architect's own app): a fresh scratch copy of `apps/ui/demo-vault`, with every showcase extension loaded as a development copy (`scripts/showcase.sh`): `examples/showcase`, the sandbox's Luau extensions (outline, surface, metronome, tidy), its process extensions (kanban, sketch, board, clicker) and `examples/extension/counter` with their programs built first, the WASI counter built for `wasm32-wasip2`, and the web view board with its Vite build. The first run builds the standard distribution (several minutes) with cargo's progress shown. The registry packages in `examples/showcase-registry` are left out on purpose | `just showcase-shots`: an isolated Loft session per width, 390 px and 1280 px, light and dark, drawn by the app itself (`APP_SHOT`) into `target/showcase/desktop/` (`scripts/showcase-shots.sh`; its steps open vault paths and run actions) |
| Web | `/app/?showcase`: the web app's demo mode on the same vault, in the tab's memory (`apps/web/src/demo.rs`). The desktop screenshots so far come from `just showcase-shots plain`
(Architect's own app with the same vault and examples), while `just
showcase` runs the standard distribution by default; the standard
distribution's shots are `just showcase-shots standard`, after building
it.

`just showcase-publish PUSH=1` puts the screenshots on the `media` branch
under `710-showcase/<platform>/`, where the cells below link them.

## How to read a cell

| Mark | Means |
|---|---|
| ✅ | Works, shown by a showcase example, with a test and screenshots on that platform. |
| ⚠️ | Works in part (the cell says what is missing), **or** the mechanism works and has a test but the showcase has no evidence on that platform yet ("not shown"). |
| ❌ | Does not run there. The cell gives the reason and the issue. |
| n/a | The capability is not about that platform. |

Since #713 the app's host gives extensions the person's opened vault
(`architect_navigator::documents::VaultDocuments`); the in-memory sample
documents (`apps/ui/src/extensions.rs` `documents`) are the sandbox's
only when it has no vault on disk.

The seed is the parity re-run of 2026-11-14 against `0ec8b0a9` (every
verdict read from code, nothing run) and the tests named in the evidence
column. iOS cells marked "not shown" are what the shared `apps/ui` host
should do there; nobody has run them on a phone for this page yet.
The iOS screenshots are the iOS Simulator's (iPhone 16e at 390 pt, iPad
Air 11-inch, iOS 27) on airlock, with the Architect app built from `main`
(`apps/mobile/ios/build-app.sh`) on a scratch copy of the showcase vault
and the showcase examples as development copies, driven through the
control socket (`architect-actions`); they are dark only, as the iOS app
is. A phone's own run is owed for every iOS cell.

**Web.** The web app runs its distribution's linked extensions on the
same host as the desktop app (#495, W1: `architect_web::run`,
`apps/web/src/app/extensions.rs`). Installed Luau and TypeScript
extensions and TypeScript pages run there too, from the registry the app
carries (`apps/web/src/app/installs.rs`): Luau on luau-web's Luau in a Web
Worker per run (`features/pages/src/web/luau.rs`, #812), its host calls
the same host service. WASI is still to come: a web cell that says only
"#495" waits on it.
