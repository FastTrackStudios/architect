# apps/site

Architect's site, `architect.fasttrackstudio.app` (#534): a TanStack Start
app (React 19), every page prerendered to static files and deployed to
Vercel as prebuilt output with the docs at `/docs/`. The web app (`/app`)
and share links (`/s/…`) are not served here: the site redirects them to
the node (`NODE_ORIGIN` in `src/content/site.ts`, an open decision).

It follows FastTrackStudios/fasttrackstudio.app (the hub): the same
TanStack Start, Router, React, Vite, biome and TypeScript versions, words
and addresses in `src/content`, `pageHead()` for every page's head, and a
committed `src/routeTree.gen.ts` that CI checks for drift. Nothing in
cargo sees this folder.

## Quick start

bun and node come from nixpkgs (`nix shell nixpkgs#bun nixpkgs#nodejs_22`,
or a bun on your PATH; the repo's dev shell has neither).

```bash
bun install --frozen-lockfile
bun run dev          # http://localhost:3000
```

| Command | What it does |
| --- | --- |
| `bun run dev` | dev server with HMR (copies the landing media first) |
| `bun run build` | every page prerendered into `.output/public` |
| `bun run data` | refreshes `src/data/*.json` from GitHub and the store's index (fail-soft) |
| `bunx biome check --write .` | lint + format |
| `bunx tsc --noEmit` | typecheck |
| `bun scripts/check-links.ts .output/public` | every internal link and asset resolves |
| `DOCS_DIR=… bash scripts/assemble.sh` | the deploy: `.vercel/output` (Build Output API v3) |
| `bun scripts/serve.ts .vercel/output 4173` | serve the deploy locally, its redirects and clean URLs applied |

`src/routeTree.gen.ts` is generated by the Vite plugin during `dev` and
`build` and committed; do not run the standalone `tsr generate`, which
emits a different file (the hub's rule).

## Layout

```
src/
  content/    the words and addresses: site.ts (identity, NODE_ORIGIN, nav),
              landing.ts (the landing page's few words and its captures), pages-copy.ts
              (/download, /changelog, /extensions, 404), pages.ts (what is
              prerendered)
  data/       build-time data, committed as the last good copy:
              release.json, changelog.json, extensions.json (scripts/data.ts)
  lib/        pageHead() (seo.ts), the light/dark theme (theme.ts), typed data
  components/
    landing/  the hero and its screenshot tabs, a feature (one heading,
              one capture), the downloads
    layout/   the header, the theme switch, the footer, a page, 404
    ui/       Rich (the content's inline markup), a capture, a command line
  styles/     tokens.css (the design tokens: colour, type, space, in one
              file the hub can adopt), base.css, site.css (the shell),
              landing.css, pages.css
  routes/     /, /download, /changelog, /extensions, /extensions/$id, /404
scripts/      data.ts, assets.sh, check-links.ts, vercel-config.ts,
              assemble.sh, serve.ts (Bun scripts, not typechecked by tsc,
              as the hub's tools/)
```

The look is a clean slate (#559): two neutrals and ink, light and dark,
no brand colour; the only colour on a page is the app in its screenshots.
`--accent` and `--on-accent` default to ink, so a product built on these
tokens adds its colour by setting those two. The page reads fully with
scripts off: the screenshot tabs are radios and labels (`:has(:checked)`).

## Data, at build time

`scripts/data.ts` writes `src/data/*.json`:

- `release.json`: the latest release and its updater manifests
  (`latest-linux.json`, `latest-macos.json`), for `/download`
- `changelog.json`: the last 20 releases' notes (the GitHub release
  bodies, `scripts/release-notes.sh`'s output), rendered to HTML
- `extensions.json`: the store's index (`extensions/index.toml` at this
  commit), each id at its newest version. While the store lists nothing,
  it is built from `examples/registry/index.toml` and the page says so.

A source that cannot be read keeps the committed file and warns; the
build never fails on the network. `GITHUB_TOKEN` is sent when set.

## Media

Real captures only, from the scenarios (#133). Two sources, both copied
into `public/` by `scripts/assets.sh` at `dev` and `build`:

- `apps/web/landing` (the old page's clips, posters, and the font), until
  it is retired;
- `media/`: this site's own WebPs, derived from the orphan `media` branch
  (and Studio's share-page capture) by `scripts/media.sh`, which names
  every source and crop. They are committed as the last good copy, the
  way `src/data` is, so a build needs no network and no encoder.

## Deploy

`.github/workflows/site.yml`. Build Output API v3: `static/` (this app's
`.output/public` plus the docs at `static/docs/`) and `config.json`
(`scripts/vercel-config.ts`: the `/app` and `/s/*` redirects first, the
404 page, clean URLs as `overrides`). The Nitro server build is never
deployed. See "The site" in `docs/content/guide/shipping.md`.
