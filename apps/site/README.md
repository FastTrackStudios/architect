# apps/site

Architect's site, `architect.fasttrackstudio.app` (#534): a TanStack Start
app (React 19), every page prerendered to static files. It is the root of
the release's web bundle (`scripts/web-bundle.sh`, with the docs at
`/docs/` and the web app at `/app/`), which the VPS serves as static files
by the rules in `scripts/web-routes.md`. The web app (`/app/`) and share
links (`/s/…`) are same-origin paths the site links to, not pages of its
own (`NODE_PATHS` in `src/content/site.ts`).

It follows FastTrackStudios/fasttrackstudio.app (the hub): the same
TanStack Start, Router, React, Vite, biome and TypeScript versions, words
and addresses in `src/content`, `pageHead()` for every page's head, and a
committed `src/routeTree.gen.ts` that CI checks for drift. Nothing in
cargo sees this folder.

## Quick start

bun and node come from nixpkgs (`nix shell nixpkgs#bun nixpkgs#nodejs_22`,
or a bun on your PATH; the repo's dev shell has neither).

```bash
bun install --frozen-lockfile
bun run dev          # http://localhost:3000
```

| Command | What it does |
| --- | --- |
| `bun run dev` | dev server with HMR |
| `bun run build` | every page prerendered into `.output/public` |
| `bun run data` | refreshes `src/data/*.json` from GitHub and the store's index (fail-soft; strict for `SITE_RELEASE_TAG`) |
| `bunx biome check --write .` | lint + format |
| `bunx tsc --noEmit` | typecheck |
| `bun scripts/check-links.ts .output/public` | every internal link and asset resolves |
| `bun scripts/serve.ts .output/public 4173` | serve a build (or a whole bundle) by the bundle's rules: P, P.html, P/index.html, else 404.html |

`src/routeTree.gen.ts` is generated by the Vite plugin during `dev` and
`build` and committed; do not run the standalone `tsr generate`, which
emits a different file (the hub's rule).

## Layout

```
src/
  content/    the words and addresses: site.ts (identity, NODE_PATHS, nav),
              landing.ts (the landing page's few words and its captures), pages-copy.ts
              (/download, /changelog, /extensions, 404), pages.ts (what is
              prerendered)
  data/       build-time data, committed as the last good copy:
              release.json, changelog.json, extensions.json (scripts/data.ts)
  lib/        pageHead() (seo.ts), the light/dark theme (theme.ts), typed data
  components/
    landing/  the hero, the pillars (what Architect is, one claim at a
              time), their animated line figures, the downloads
    layout/   the header, the theme switch, the footer, a page, 404
    ui/       Rich (the content's inline markup), a command line, icons
  styles/     tokens.css (the design tokens: colour, type, space, in one
              file the hub can adopt), base.css, site.css (the shell),
              landing.css, pages.css
  routes/     /, /download, /changelog, /extensions, /extensions/$id, /404
scripts/      data.ts, check-links.ts, serve.ts (Bun scripts, not
              typechecked by tsc, as the hub's tools/)
```

The look is a clean slate (#559): two neutrals and ink, light and dark,
no brand colour. `--accent` and `--on-accent` default to ink, so a product
built on these tokens adds its colour by setting those two. What is not
shipped yet is a dashed chip that links to its issue. The page reads fully
with scripts off.

## Data, at build time

`scripts/data.ts` writes `src/data/*.json`:

- `release.json`: the latest release and its updater manifests
  (`latest-linux.json`, `latest-macos.json`), for `/download`
- `changelog.json`: the last 20 releases' notes (the GitHub release
  bodies, `scripts/release-notes.sh`'s output), rendered to HTML
- `extensions.json`: the store's index (`extensions/index.toml` at this
  commit), each id at its newest version. While the store lists nothing,
  it is built from `examples/registry/index.toml` and the page says so.

A source that cannot be read keeps the committed file and warns; a local
or PR build never fails on the network. A release's build sets
`SITE_RELEASE_TAG` (through `scripts/web-bundle.sh`'s
`ARCHITECT_RELEASE_TAG`): `/download` then describes that tag, and any
failure, a missing Linux manifest or a changelog without the tag fails
the build. `GITHUB_TOKEN` is sent when set.

## Deploy

Nothing here deploys. `scripts/web-bundle.sh` builds this app (or takes
its `.output/public` as `ARCHITECT_SITE`) and puts it at the root of the
web bundle; the release attaches the bundle as
`architect-web-<X.Y.Z>.tar.gz` and the VPS serves it. The Nitro server
build is never shipped. `.github/workflows/site.yml` checks a pull
request, the bundle included (`scripts/check-web-bundle.sh`). See "The
site" in `docs/content/guide/shipping.md`.
