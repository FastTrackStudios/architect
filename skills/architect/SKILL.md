# The architect way

[FastTrackStudios/architect](https://github.com/FastTrackStudios/architect) is the fleet's Rust application framework: entities, vox RPC, HTTP/SSE faces, auth, permissions, CRDT sync, offline queues, commands + MCP, keymaps, telemetry and `architect-ui`. The Captain's goal: Task, Signal and Session get local-first, offline, peer-to-peer collaboration and enforced app boundaries **by building on architect**, not by hand-rolling plumbing per app. Reach for it first, and check the map below before writing any generic plumbing.

Every architect path in this skill is checked by `cargo xtask docs` against the architect repo; `task:` and `studio:` paths name the Task and studio repos.

Paperclip projects: **Architect** and **fts-auth**. Wiki: `architect` (Task org fasttrackstudio).

## When to Use

- Designing a feature, service, entity, command, keymap or synced document in Task, Signal, Session (studio) or architect.
- Replacing hand-written DTOs, axum routes, SeaORM repos, MCP catalogues, menu handlers, Loro sync glue, env parsing, token stores, self-updaters.
- Writing or reviewing an issue/PR in those repos.
- Sign-in or accounts: also read `references/fts-auth.md` (deployment) and `references/auth-permissions.md` (API).

## Before you rely on a version

- Tags land several times a day. Run `gh release list -R FastTrackStudios/architect -L 3` for the latest, and read the consumer's root `Cargo.toml` (`[workspace.dependencies]`, plus any `[patch]` of architect) for what it pins. Each tag's GitHub Release says what it shipped (notes from `.changes/`); `CHANGELOG.md` covers tags up to v0.10.0.
- When the consumer pins an older tag than the feature you want, repin first (recipe below); don't copy the code across.
- Vox handshakes fail across mismatched vox revisions: server and every client pin one architect tag.
- When the docs (`docs/content/`) and the code disagree, trust the code. `examples/greeter` is the reference feature.

## Rules

1. **Contract first, once.** Every capability is a Rust type or trait: `#[architect::entity]`, `#[architect::error]`, `#[architect::service]` (vox + HTTP, optionally `actions`) or `#[architect::rpc]` (vox only). Never write a second DTO, a hand axum route or a Dioxus server function for something a trait already describes. Wire types are facet-only (no serde next to them; the Entity `json` option and an action's `RawJson` reply are the documented exceptions). One error enum per service. Keep a method to at most 4 params (a convention, not compiler-enforced); more go in one facet struct. Subscriptions are sync `#[subscribe]` markers, not `async fn`.
2. **One command per capability.** Anything a person or an agent can do is an action in the app's `ActionList`: id `AREA_VERB`, facet `Args`/`Out`, an `Effect` (ReadOnly/Mutating/Destructive). Keys (`architect-input`), menus, palette, MCP, CLI and REAPER named commands all run it by id. A service's methods become actions with `#[architect::service(actions)]`. No bespoke MCP tool, menu handler or palette entry. UI-only effects use the queued-window pattern (`studio:apps/session/daw/src/actions.rs` `take_window`); a programmatic `run` never opens a dialog. Register at startup and call `list.validate()` in a test.
3. **Pick the state model per datum.**

   | Data | Model |
   |---|---|
   | Co-edited document (chart, setlist, note) | CRDT doc (`crdt`, Loro) |
   | Long text edited concurrently | `#[architect(crdt(text))]` on the `String` field, or an explicit `LoroText` child (`apply_text_ops`); never a plain derived `String` (that is last-writer-wins) |
   | Computed record / call made offline (timer start) | `atom` `CallQueue` (`Mutation::run_queued`) |
   | Server-owned rows | optimistic `Store` + persisted `LocalRows` |
   | Live signal (meters, playhead) | `PubSub`, never CRDT |
   | Bytes / files | `architect::blob` (`ResumableFetch`, `BlobStore`) for verified transfer; Task's Files lane (blake3 chunks, iroh-blobs) stays app-specific |
   | Audio/images a document points at | by sha256 in the doc, `DocKind::blobs` reads them; bytes in a `blob::LocalFs` beside it, fetched on demand (`blob::Fetcher`), pinned offline, collected with `crdt::blobs::live`; never the bytes in the Loro doc |

   Build and test against `LocalServer` first; every feature must work with the network off.
4. **Every node is a peer** (ADR 0006, Proposed). No code path only a server has. Dial by iroh endpoint id; identify peers as `Principal::Host`; check access per document in the library (`DocRegistry::with_authorizer` sees the caller). Test with three nodes and the always-on host stopped. A directory (fts-auth, n0 relays) must never be the only way to find a peer; LAN lookup exists behind `iroh-lan`.
5. **Boundaries are dependency directions, enforced.** L0 contract (wasm-clean: no tokio runtime, sea-orm, dioxus, axum, iroh) → L1 engine → L2 storage → L3 host/transport (only under `apps/*`) → L4 UI (L0 + `architect[client]` only). Run `cargo xtask boundaries` (rows in `boundaries.toml`, baseline counts ratchet down only). Every mounted service has a permit table (`PermissionsGate::coverage` empty). One architect tag per `Cargo.lock`; a branch `[patch]` only as a labelled experiment. Every crate has `[lints] workspace = true`.
6. **Prove it on every wire.** The same scenario test runs direct, `LocalServer`, WebSocket, iroh, HTTP and, for a service with `actions`, named MCP (copy `apps/auth-server/tests/surfaces.rs`, `examples/greeter/tests/round_trip.rs` and `examples/greeter/tests/mcp.rs`). A bug fix lands with a test that failed before it. Build discipline: `rust-build-efficiency`; function design: `perfect-functions`.

## Pitfalls

- `run_json` (keys, menus) is the trusted door and **refuses an async action** rather than block: spawn `run_json_async` there (the ⌘K palette does). Only the `_as` / `_with` doors consult the authorizer. `infos()` is unfiltered; use `infos_for(&principal)` for a model or peer. Derived `#[architect::actions]` land as `Mutating` with no schema.
- The router `PermissionsGate` does **not** cover in-process `ActionList` runs: two authorization planes until the app wires `set_authorizer` with the gate's engine.
- `#[architect::service(actions)]` handlers do not see the caller (they register through `register_async`); a per-org service registers by hand with `register_async_with`. A projected action's failure is the error's `Display`, not the HTTP face's `{code, message}`. Not available for `context = T` traits.
- The MCP HTTP face runs every request as the server's one principal; a per-request caller needs `handle_as` / `handle_with` from your own transport. The bearer token is a gate, not an identity.
- An app's Dock and tray presence is `architect-presence`'s `AppPresence` (`app-presence.md`), not a hand-rolled `NSStatusItem` or LaunchAgent: its menus are Action List `Menu`s, its toggles are actions. Call `single_instance` before the launch and start the window with `with_visible(!launched_in_background())`; the close only hides under the workspace launcher (`MainWindow`). A login item is written only from an installed copy.
- The menu bar is `architect-commands`' `MenuBar`, built from the commands (`app-menus.md`). Its states follow the Action List's events: when what an enabled or checked check reads changes outside an action run, call `list.changed(…)` or the bar keeps the old state. A live section is read when the bar is resolved, on the UI thread: it may read signals.
- LAN discovery needs feature `iroh-lan` (native, multicast UDP; no-op on wasm). Nodes advertise as `_fts._udp`; `iroh_link::LanBrowser` lists them.
- `#[architect(crdt)]` needs `repo` and a `Uuid` pk; a plain `String` field is whole-string last-writer-wins, so mark prose `crdt(text)`. `crdt::sync` (`DocSync`) is hub-shaped; `crdt::peer` is the pairwise path. `DocRegistry` admission sees only the doc id; use `with_permissions` (the org's engine) or the authorizer. A device syncs an org's docs through `OrgSyncs` (one `OrgDocs` per org, `Placement` for the files), never a hand-rolled reconnect loop.
- `architect::host::init_tracing` (fmt only) is not `architect_telemetry::init_tracing` (Sentry); `wide::set` is a silent no-op without the `otel` feature; telemetry is native only.
- `#[architect::rpc]` / `service` emit `serve`, `layer`, `Service`, `stream_layer`, … unqualified at module level: one rpc trait per module, re-export via `prelude` or renames. `<Trait>Client` implements the trait only for an all-async, all-`Result` `#[architect::service]`; otherwise map its `VoxError<E>` with `architect::vox_into_app`. A `#[subscribe]` call stays in flight for the stream's life: poll it beside `rx.recv()` (`references/rpc-services-hosts.md`).
- A Dioxus task spawned from a menu row, a popup or any component that unmounts as it runs dies with it: work an action starts there goes through `Commands::run_invoked` (spawned forever) or `dioxus::core::spawn_forever`.
- An extension's view never does heavy work on its own thread, and the app's UI never waits on an extension: Luau runs off the caller's thread (await `Runtime::run`, never block on it), a long job goes to a `[[workers]]` worker (`worker.spawn`, read `job:progress()` each frame; never `join` in a view), a process view's handler starts `use_work` / `spawn_work` and returns. Provide one `architect_workspace::Meters` in context so every extension view is measured (`EXT_VIEWS`); wire its `ViewReport` to the app's status board.
- A panel, list, form, dialog or dashboard an extension shows can be a page file (`[[views]] page = "pages/x.tsx"`, `.luau` or `.a2ui.json`, `architect-pages`; `docs/content/architecture/pages.md`): its Rust crate keeps the data, actions and heavy work; the page only draws them, through actions and `useData` (an A2UI page: `bind` a data path to an action, a Button's `action` runs one), styled with theme tokens (`$foreground`), its heavy work in `worker.spawn` (TSX and Luau alike). Dense or animated views stay compiled. An agent edits a built-in's page by `PAGES_CLONE`, saves, and reads `PAGES_STATUS` (a broken save keeps the last good page and writes `<file>.error`).
- An extension's action reads where it was run from in its invocation (`ctx` in Luau, the second argument in Rust), not from arguments a key or a menu cannot pass; and its runtime state is written by the extension itself (`EXT_STATE_SET` refuses an `ext:` source).
- `SyncedDoc` does not persist what it receives unless `.durable()`; device replicas want it.
- Generated HTTP face: JSON by default (`POST /<prefix>/<method>`), any verb with path params, query arguments on a `get`, byte methods (`BodyStream` / `RequestHead` / `ByteBody`, HTTP-only) and SSE; subscriptions carry no typed errors. Media, blobs and share links are service methods now; only what neither a service nor an `EngineHost` builder covers (OAuth redirects, hosted pages) goes through `.plugin(Router)`.
- Boundaries ratchets go one way: when a count drops, lower its baseline in the same PR. Do not grandfather tags to pass the tag-order check; re-pin to a correctly numbered tag.
- Crate layout (STA-257): one crate per feature, layers as cargo features. Don't create new `-proto`/`-<backend>`/`-ui` siblings; don't split or merge existing crates as a side effect.
- Session's `studio:features/session/AGENTS.md` may still say `#[roam::service]`; it means `#[architect::rpc]`.

## Driving a running app (agents)

What herdr's CLI skill says, for any architect app (`references/commands-mcp.md`, "Agent tools"):

- **Read the app's `AGENTS.md` first**: `<app dir>/AGENTS.md`, generated by the running app from its live Action List (every action, its effect and arguments; how to change things safely), with `actions.schema.json` beside it. Don't edit either: the app rewrites them.
- **Inspect before acting:** `<app> actions run APP_STATUS` (windows, focus, layout revision, theme, open sheets, every problem with file and field), `<app> actions list` / `describe ID`. Ask the running app; don't launch a second one to look.
- **Act by id, with the exact arguments:** a misspelt name is refused with the valid ones. `confirmation_required` means a person must approve: tell them, retry with `--ticket`. Pass `if_revision` on workspace writes planned from a read.
- **Clone, don't edit, what the app ships:** `WORKSPACES_CLONE`, `EXT_CLONE`. The escape hatch (Ctrl+Alt+Shift+Escape, Cmd on macOS) resets the built-in layouts and the person's keys; tell the person about it.
- **Check your work:** after an extension change, `EXT_CHECK {folder}` until `ok`; then `APP_STATUS` and `<app> actions shot /tmp/x.png`, and look at the picture. Never call a visual change done without a shot you looked at.
- Never drive the person's real display to test: run the app in a test session (Loft's `loft-dev`), and stop only what you started.

## Where changes go

- Framework gaps go **upstream into architect** as Architect-project issues, then a tag, then a repin. Don't fork the fix into an app.
- A PR to architect that adds, renames or removes public API or a feature flag updates this skill (`skills/architect/`) in the same PR.
- A PR to architect that changes a crate adds a cargo-rail change file (`cargo rail change add <crates> --bump <none|patch|minor|major> -m "<note>"`, rules in `.changes/README`); `pr.yml` enforces it. Release notes come from those files, never from commits.
- Auth engine changes go to `features/auth` / `apps/auth-server`; fts-auth is only the deployment shell.
- The adoption backlog is in the Architect project; check it before starting overlapping work.
