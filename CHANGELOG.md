## [0.9.21] - 2026-10-22

### Features

- *(architect)* Async actions: `ActionList::register_async` / `register_dynamic_async` take handlers that answer with a future (`ActionFuture`, `AsyncHandler`), run with `run_json_async` / `run_json_async_as` (which run sync actions too). Arguments are decoded before the future exists. The panic guard, enabled check and authorizer apply as on the sync door. `probe_hostile_args` decodes async actions without polling them, and the sync `run_json` refuses an async action rather than block. `is_async(id)` (STA-261)
- *(rpc-derive)* `#[architect::service(actions)]` (or `actions = "NS"`) projects every method into an Action List with one call: `http::actions::register(backend, &list)` (prelude `<snake>_actions`), one async action per method, id `NS_METHOD`, its doc comment the description, `http::<Method>Args` the params. Per-method `#[action(effect = read_only | mutating | destructive, id, name, category, skip)]`; the effect defaults to `mutating`. Opt-in, so nothing changes for existing `service` users. Method-level `#[http(...)]` / `#[action(...)]` are now stripped from the re-emitted trait (STA-261)
- *(mcp)* Named tools: `Server::with_tools(Tools::Named | Tools::Both)` lists each action as its own MCP tool (description, params schema as `inputSchema`, `Effect` as hints), named its lower-cased id unless `with_tool_name(id, name)` keeps an agent's existing name. Async core `handle_async` / `handle_as_async`; `handle` drives it on the calling thread (STA-261)
- *(greeter)* `examples/greeter/tests/mcp.rs`: `greet` listed, described and run over named MCP answers what `POST /greeter/greet` answers, from one backend (STA-261)

### Documentation

- `commands.md`: async actions, named tools, a service as actions, and migrating a trait from `#[architect::rpc]` to `#[architect::service]` (trait, backend, features, clients, tests, when to stay `rpc`) (STA-261)

## [0.9.20] - 2026-10-22

### Features

- *(architect-derive)* `#[architect(crdt(text))]` on a `String` field of a `#[architect(crdt)]` entity stores it as a `LoroText` child container written by minimal diff (`crdt::codec::write_text`), so concurrent edits from two peers both survive the merge. Plain fields stay last-writer-wins. Legacy plain-string rows still decode (`read_text_or_legacy`) and upgrade on the next write. Non-`String` fields, and the attribute without the container's `crdt`, are derive-time errors (STA-271)
- *(crdt)* `crdt::schema`: `schema_version` / `set_schema_version` / `migrate(doc, target, &[Migration])`. Ordered, per-step-committed migration hooks; refuses a doc newer than the app (`RepoError::Conflict`); `SchemaStamp::new(root, key)` adopts an existing stamp location (Session's `meta.schema`) (STA-271)
- *(crdt)* `codec::upgrade_to_text`: legacy string → `LoroText` via a plain container, so concurrent upgrades resolve LWW instead of duplicating the seed (which `read_text_with_migration`'s mergeable container does) (STA-271)

## [0.9.19] - 2026-10-22

### Features

- *(architect)* `architect::snapshot` (feature `snapshot`, STA-399): `WriteGate` parks new vox calls while a snapshot holds it (`pause()` → `GateHold`, one hold at a time); every hold is bounded by `max_hold` (default `DEFAULT_MAX_HOLD` = 30 s): past it waiters are admitted (`Admission::Expired`) and `quiesce` cancels with `GateTimeout`. `GatedLayer` wraps any vox handler; `LayerRouter::gated(&gate)` wraps a whole router and keeps its type. `quiesce(&gate, checkpoint, step)` runs the checkpoint callback then the app's step under the gate; with `server-seaorm`, `wal_checkpoint(conns)` is the sqlite `PRAGMA wal_checkpoint(TRUNCATE)` callback. The git step stays in the app (Task). Native only. See `docs/content/architecture/snapshot.md`

## [0.9.18] - 2026-10-22

### Features

- *(architect)* `architect::testing` (STA-400), extracted from Task's `apps/server/tests/it/support/`, for an app's own test binaries (dev-dependencies only). Feature `testing`: `sandbox_server(seed)` points `HOME`, `USERPROFILE`, the `XDG_*` dirs, `APPDATA` and `LOCALAPPDATA` inside a fresh tempdir under one process-wide `env_lock()`, runs the seed (plant fixtures, build the app) and serves the returned `LayerRouter`, `EngineHost` or axum `Router` on `127.0.0.1:0` (`url()` = `ws://…/vox`); the `sandbox()` builder adds `clear`, `env`, `data_env`, `boot` (no socket) and `over` (re-boot over a previous sandbox). Feature `testing-alloc`: `testing::alloc::Counting`, a counting `GlobalAlloc` (`live`, `peak`, `reset_peak`, `counters_are_this_tests`, `mib`) that architect never installs; a test binary opts in with `#[global_allocator]`. `crates/architect/tests/testing_sandbox.rs` sets `HOME` to a poisoned dir and asserts the boot never touches it; `testing_alloc_uninstalled.rs` asserts linking the feature installs nothing. See `docs/content/architecture/testing.md`

## [0.9.17] - 2026-10-22

### Features

- *(host)* `EngineHost` serves `GET /version.json` (STA-391): `{"rev", "version", "built_at"}` from `host::BuildInfo`, set with `.build_info(architect::build_info!())`. The macro reads the binary crate's `CARGO_PKG_VERSION` and the build-time env `ARCHITECT_BUILD_REV` / `ARCHITECT_BUILT_AT` (`host::BUILD_REV_ENV`, `host::BUILT_AT_ENV`); unset or empty values are `null`. ## [0.9.16] - 2026-10-22

### Features

- *(architect)* `architect::blob` (feature `blob`, STA-388): `ResumableFetch` fetches one file from any offset-addressable `Source` into place: `.part` resume, sha256 verify over the resumed prefix and the new bytes, a wrong hash removes the `.part` and retries, `<file>.sha256` sidecar so a file already here is skipped without reading it, synced atomic rename, one transfer per file (`BlobError::Busy`). `BlobStore` (object-safe: put by hash, get as a stream, has) with the `LocalFs` backend at `<root>/<hex[0..2]>/<hex>`. Native only; the wasm OPFS ledger is a follow-up. See `docs/content/architecture/blob.md`

## [0.9.15] - 2026-10-22

### Features

## [0.9.11] - 2026-10-21

### Features

- *(architect)* A hardened Action List (STA-260). `ActionList::set_enabled(id, check)`: an action can be disabled with a reason, shown as `ActionInfo::enabled` / `disabled_reason` and answered `ActionError::Disabled`. `ActionList::set_authorizer(engine)` with `run_json_as` / `run_as(principal, ...)` and `infos_for` / `info_for(principal, ...)`: a caller sees and runs only what the engine allows (`ActionError::Denied`). A panicking handler is caught and answered `ActionError::Failed` (`"panicked: ..."`). `ActionList::validate()` (duplicate ids and shortcuts, non-`AREA_VERB` ids, schemas that are not JSON objects) and `ActionList::probe_hostile_args()` (every action survives `{}` and refuses malformed JSON, `HOSTILE_ARGS`) are an app's registry test
- *(architect)* An action's arguments must be one well-formed JSON value, at most `MAX_ARGS_DEPTH` (128) deep, with nothing after it, before any decoder sees them: `facet_json` alone accepted `{"a":1} junk`, and a deep nesting no longer reaches a recursive decoder
- *(permissions)* `PermissionEngine::authorize(principal, action_id)`, defaulting to `check(principal, "action/<id>", "run")` (`action_resource`, `Action::RUN`); `Arc<T>` forwards it
- *(mcp)* Every call runs as a `Principal` (`Server::with_principal`, `Server::handle_as`): `actions`, `describe` and `actions://list` show only what it may run, and `run` and each `batch` step are authorized. `actions` / `describe` carry `enabled` and `disabled_reason`. A `batch` runs at most `MAX_BATCH_STEPS` (64) steps and says it is not atomic

### Breaking

- `ActionList::register` and `register_dynamic` return `Result<(), ActionError>`: a duplicate id is `Err(ActionError::Duplicate)` and no longer replaces the first. `ActionError` has three new variants (`Denied`, `Disabled`, `Duplicate`); `ActionInfo` two new fields

## [0.9.9] - 2026-10-21

### Features

- *(crdt)* `crdt::peer`: documents move between nodes pairwise, with no hub. The `DocPeer` lane (`list`, `sync` by `DocAt`), `DocPeerHost` over a `DocRegistry` and a `DocCatalog` serving only the `Principal::Host` callers it admits, `exchange` (one document, both directions, through an in-memory pipe), `pull` (a sweep against one peer, with a `PullReport`), `SelfLane` (a node's own registry behind a fixed-principal gate), and a foreign-lineage refusal (`is_foreign_lineage`, `check_lineage`). Lifted from Task's `vault-doc::peer` and `doc_peer`
- *(crdt)* `DocRegistry::with_authorizer`: a per-attach hook that receives the caller the router's permissions gate resolved (`permissions_gate::caller()`) and the doc id; a refusal answers `UnknownDoc`
