## [0.9.10] - 2026-10-21

### Features

- *(xtask)* `cargo xtask boundaries`: the crate-layout ADR (`docs/content/architecture/layout.md`) as a check. A root `boundaries.toml` layer table maps a package + feature set to L0-L4; each row is resolved with `cargo tree -p` (L0 for wasm32). Rules `contract-clean`, `ui-reach`, `transport-host`, `lints`, `single-source`, `unmapped`, plus ratcheted `[[idiom]]` source counts (`hand-routes`). `[baseline]` ratchets both ways. Wired into checks.yml; Task and studio adopt it with their own tables (STA-268)

## [0.9.9] - 2026-10-21

### Features

- *(crdt)* `crdt::peer`: documents move between nodes pairwise, with no hub. The `DocPeer` lane (`list`, `sync` by `DocAt`), `DocPeerHost` over a `DocRegistry` and a `DocCatalog` serving only the `Principal::Host` callers it admits, `exchange` (one document, both directions, through an in-memory pipe), `pull` (a sweep against one peer, with a `PullReport`), `SelfLane` (a node's own registry behind a fixed-principal gate), and a foreign-lineage refusal (`is_foreign_lineage`, `check_lineage`). Lifted from Task's `vault-doc::peer` and `doc_peer`
- *(crdt)* `DocRegistry::with_authorizer`: a per-attach hook that receives the caller the router's permissions gate resolved (`permissions_gate::caller()`) and the doc id; a refusal answers `UnknownDoc`

## [0.9.8] - 2026-10-21

### Features

- *(iroh)* LAN peer discovery (feature `iroh-lan`, native only): `iroh_link::PeerLookup` (`N0` default, `N0AndLan`, `Lan`), `iroh_link::endpoint_builder` and `iroh_link::bind_endpoint_with`, backed by `iroh-mdns-address-lookup` (iroh 1.x moved mDNS out of core). Two endpoints on one LAN dial each other by bare `EndpointId` with no internet
- *(host)* `EngineHost::iroh_lookup(PeerLookup)` picks how a host's iroh endpoint finds peers

### Documentation

- `docs/content/architecture/http.md`: finding iroh peers on the LAN; `examples/iroh_lan.rs` is the two-machine manual check

## [0.9.7] - 2026-10-21

### Features

- *(architect)* The Action List (`architect::action::ActionList`, feature `action-list`): one registry every key, menu, palette, CLI and model runs an app's commands through, with facet-typed arguments and results and an `Effect` (read-only, mutating, destructive) per action
- *(architect)* `architect::schema::json_schema`: a facet type as JSON Schema; a flattened struct is its fields
- *(mcp)* New crate `architect-mcp`: an app's Action List as an MCP server (`actions`, `describe`, `run`, `batch`, `watch`), over stdio or, with feature `http`, `POST /mcp` behind a bearer token and a localhost origin guard; `http::serve(listener, server, token)` for an app to spawn
- *(telemetry)* `architect_telemetry::timing`: stage timings kept in-process (`Stages`, `Recorder`, `recent`), a span per action, `DIRECTIVES` to let them through a quiet filter

### Documentation

- `docs/content/architecture/commands.md`: commands and the Action List
