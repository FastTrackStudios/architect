## [0.9.15] - 2026-10-22

### Features

- *(architect)* `architect::capability` (feature `capability`, STA-389): Ed25519-signed, expiring capability tokens, `base64url(sig || "cap/v1|purpose|expiry|subject")`, extracted from the Task server's signed blob URLs. `Capability::verify(token, expected_purpose, key, now)` fails closed on tamper, another key, wrong purpose, expiry, oversized or non-canonical input. `ServerKeypair::load_or_generate` creates the seed file `0600` at open and refuses a group- or world-accessible or wrong-length key file. See `docs/content/architecture/capability.md`

## [0.9.14] - 2026-10-22

### Features

- *(mcp)* MCP discovery and loopback serve in `architect-mcp`, moved out of Session's `mcp_server.rs` (STA-385). `publish(name, url, token)` writes `<config>/fts/<name>-mcp.json` (`{"url", "token"}`, created `0600` and renamed into place, so the token is never readable by anyone else); `read`, `unpublish` and `*_in(config_dir, ..)` variants; `project_mcp_json(dir, name, url)` names the server in a project's `.mcp.json` for Claude Code, keeping every other entry and leaving the file untouched when it already says the same. Behind `http`: `Server::serve_loopback(port_env, token_env)` (and `serve_loopback_or(default_port, ..)`) binds `127.0.0.1`, reads the port and an optional token from the app's variables, returns `None` when `FTS_MCP=0`, and spawns `http::serve`; `Serving::publish(name)` says where it is. The Origin guard and bearer check in `http::message` are unchanged. A test calls `tools/list` over the URL read back from the published file with its token; `docs/content/architecture/commands.md` section 5

## [0.9.13] - 2026-10-22

### Features

- *(telemetry)* `architect_telemetry::flight` (`flight` feature, native only, no new dependency): the crash flight recorder moved out of studio's `log_ring.rs` (STA-384). `RingLayer` keeps the last 600 `tracing` events in a process-wide ring (`snapshot()`); `install_panic_recorder(app_dir)` chains a panic hook that appends the panic, a backtrace and the lines before it to `<app_dir>/crash.log` and writes the ring to `<app_dir>/flight-log.txt`; `restore_previous()` puts the previous run's last lines back into the ring at launch. Composes with `architect::host::install_panic_logger` in either order without logging the panic twice. `tests/flight.rs` panics in child processes and reads the files back; `docs/content/architecture/flight-recorder.md`

## [0.9.12] - 2026-10-22

### Features

- *(architect)* `architect::http::ranged`: `Range: bytes=…` → `206 Partial Content` (STA-383). The pure `parse_range(raw, total) -> ByteRange` (open range, suffix, clamping, `416` for a well-formed spec that selects nothing, anything malformed or multi-range ignored and served whole) builds in every configuration; under `http`, `range_of`, `respond`, `serve_bytes` and `serve_body` (the caller reads only the selected window, never for a `416`); natively, `serve_file` and `reader_body` (any `AsyncRead` as a streamed body). Moved out of Task's attachment download; `docs/content/architecture/http.md` says when to use `tower_http::ServeFile` instead
- *(architect)* `architect::settings` (`settings` feature): `Store<T>` keeps a facet value as JSON in the app's config dir (`$<APP>_CONFIG_DIR` override) or in `localStorage` on wasm, under the same key on both. Writes are atomic (temp file, sync, rename), skipped when the body is unchanged, and optionally `0600`. `FileKv` is the directory-of-files store underneath; with `atom-persist` it implements architect-atom's `Kv` (STA-390)
- *(xtask)* `cargo xtask feature new` scaffolds the one-crate layout (STA-322)

### Documentation

## [0.9.11] - 2026-10-21

### Features

- *(architect)* A hardened Action List (STA-260). `ActionList::set_enabled(id, check)`: an action can be disabled with a reason, shown as `ActionInfo::enabled` / `disabled_reason` and answered `ActionError::Disabled`. `ActionList::set_authorizer(engine)` with `run_json_as` / `run_as(principal, ...)` and `infos_for` / `info_for(principal, ...)`: a caller sees and runs only what the engine allows (`ActionError::Denied`). A panicking handler is caught and answered `ActionError::Failed` (`"panicked: ..."`). `ActionList::validate()` (duplicate ids and shortcuts, non-`AREA_VERB` ids, schemas that are not JSON objects) and `ActionList::probe_hostile_args()` (every action survives `{}` and refuses malformed JSON, `HOSTILE_ARGS`) are an app's registry test
- *(architect)* An action's arguments must be one well-formed JSON value, at most `MAX_ARGS_DEPTH` (128) deep, with nothing after it, before any decoder sees them: `facet_json` alone accepted `{"a":1} junk`, and a deep nesting no longer reaches a recursive decoder
- *(permissions)* `PermissionEngine::authorize(principal, action_id)`, defaulting to `check(principal, "action/<id>", "run")` (`action_resource`, `Action::RUN`); `Arc<T>` forwards it
- *(mcp)* Every call runs as a `Principal` (`Server::with_principal`, `Server::handle_as`): `actions`, `describe` and `actions://list` show only what it may run, and `run` and each `batch` step are authorized. `actions` / `describe` carry `enabled` and `disabled_reason`. A `batch` runs at most `MAX_BATCH_STEPS` (64) steps and says it is not atomic

### Breaking

- `ActionList::register` and `register_dynamic` return `Result<(), ActionError>`: a duplicate id is `Err(ActionError::Duplicate)` and no longer replaces the first. `ActionError` has three new variants (`Denied`, `Disabled`, `Duplicate`); `ActionInfo` two new fields

## [0.9.10] - 2026-10-21

### Features

- *(xtask)* `cargo xtask boundaries`: the crate-layout ADR (`docs/content/architecture/layout.md`) as a check. A root `boundaries.toml` layer table maps a package + feature set to L0-L4; each row is resolved with `cargo tree -p` (L0 for wasm32). Rules `contract-clean`, `ui-reach`, `transport-host`, `lints`, `single-source`, `unmapped`, plus ratcheted `[[idiom]]` source counts (`hand-routes`). `[baseline]` ratchets both ways. Wired into checks.yml; Task and studio adopt it with their own tables (STA-268)

## [0.9.9] - 2026-10-21

### Features

- *(crdt)* `crdt::peer`: documents move between nodes pairwise, with no hub. The `DocPeer` lane (`list`, `sync` by `DocAt`), `DocPeerHost` over a `DocRegistry` and a `DocCatalog` serving only the `Principal::Host` callers it admits, `exchange` (one document, both directions, through an in-memory pipe), `pull` (a sweep against one peer, with a `PullReport`), `SelfLane` (a node's own registry behind a fixed-principal gate), and a foreign-lineage refusal (`is_foreign_lineage`, `check_lineage`). Lifted from Task's `vault-doc::peer` and `doc_peer`
- *(crdt)* `DocRegistry::with_authorizer`: a per-attach hook that receives the caller the router's permissions gate resolved (`permissions_gate::caller()`) and the doc id; a refusal answers `UnknownDoc`

## [0.9.8] - 2026-10-21

### Features

- *(iroh)* LAN peer discovery (feature `iroh-lan`, native only): `iroh_link::PeerLookup` (`N0` default, `N0AndLan`, `Lan`), `iroh_link::endpoint_builder` and `iroh_link::bind_endpoint_with`, backed by `iroh-mdns-address-lookup` (iroh 1.x moved mDNS out of core). Two endpoints on one LAN dial each other by bare `EndpointId` with no internet
- *(host)* `EngineHost::iroh_lookup(PeerLookup)` picks how a host's iroh endpoint finds peers

### Documentation

- `docs/content/architecture/http.md`: finding iroh peers on the LAN; `examples/iroh_lan.rs` is the two-machine manual check

## [0.9.7] - 2026-10-21

### Features

- *(architect)* The Action List (`architect::action::ActionList`, feature `action-list`): one registry every key, menu, palette, CLI and model runs an app's commands through, with facet-typed arguments and results and an `Effect` (read-only, mutating, destructive) per action
- *(architect)* `architect::schema::json_schema`: a facet type as JSON Schema; a flattened struct is its fields
- *(mcp)* New crate `architect-mcp`: an app's Action List as an MCP server (`actions`, `describe`, `run`, `batch`, `watch`), over stdio or, with feature `http`, `POST /mcp` behind a bearer token and a localhost origin guard; `http::serve(listener, server, token)` for an app to spawn
- *(telemetry)* `architect_telemetry::timing`: stage timings kept in-process (`Stages`, `Recorder`, `recent`), a span per action, `DIRECTIVES` to let them through a quiet filter
